# Checkpoints, death and finish (M7)

Composition explicitly binds one PlayerLifecycle to each PlayerController and assigns the same ordered course IDs/mandatory subset to its independent CheckpointProgress. No nickname, save, transport, timer or animation is gameplay authority. Map composition selects strict ordering (default true); unordered maps still require all mandatory IDs. Unknown/duplicate course IDs and unknown mandatory IDs are rejected. Failed configuration leaves the previous valid configuration intact. Optional checkpoints participate in strict activation order but are not independently required for Finish.

DeathZone is a reusable Area2D scene on fatal layer 4, detecting player layer 2 every physics tick, including persistent overlaps after immunity expires. Other fatal hazards must route through PlayerController.die(). Accepted death emits died once, freezes motion and clears Dash intent. PlayerLifecycle waits 27 full 60 Hz ticks (0.45 seconds), then attempts respawn on the next lifecycle tick. The existing M4 modular robot scatter/fade is reused without spawning effect objects. Presentation never schedules respawn. Normal death does not clear checkpoint progress and does not touch race clocks.

RespawnSafety checks the player's entire transformed collision shape against normal level geometry and fatal areas, then requires static support within 4 pixels below. Anchors must be authored slightly above a stationary floor (fixture: capsule centre 34 pixels above floor). AnimatableBody2D and velocity-bearing StaticBody2D supports are rejected. Author static supports as stationary; animated/reparented static geometry violates this contract. No moving platforms are implemented in M7. Unsafe activation never credits progress. Safety is checked again at death recovery; a newly blocked checkpoint falls back to Start. If both positions are blocked, stay dead, emit one localized notification and retry each physics tick. Never teleport into a collider or hazard. Future hazards must reserve layer 4 for their fatal volumes.

PlayerController.respawn_at() remains the trusted low-level relocation primitive for tests/developer tools; production death recovery uses PlayerLifecycle safety validation. Respawn clears velocity, temporary state and selected Dash direction, restores both abilities, grants 45 simulation ticks (0.75 seconds) of fatal invulnerability, and resets interpolation through the existing relocation/camera signal. Normal floor/wall collision remains enabled. M4 draws a subtle ring while invulnerable.

CheckpointTrigger receives an explicit actor-to-lifecycle registry and Marker2D anchor. Entries during locked lifecycle states or before GO are ignored. Each actor activates a checkpoint once. The local flag fill and CHECKPOINT notification provide feedback; another player's progress cannot validate the local Finish. FinishTrigger calls lifecycle.finish(): missing mandatory checkpoints produce M7_SKIPPED_CHECKPOINT without relocation or finish. Accepted Finish freezes the player and emits completed once. No results, records or time-trial mode are implemented.

ReadyStart is a pure tick gate with an explicit unique participant roster. A composition layer marks each participant ready only after map/assets and hints are complete, then schedules a future authoritative GO tick. All participants must be ready; readiness withdrawal cancels a pending schedule. advance(authoritative_tick) releases once at or after GO. StartBarrier freezes explicitly registered actors and releases them together; caller advances it before player physics. Configure a fresh roster for each round. This is an independently testable primitive, without online transport, synchronization estimation, lobby or round logic.

Run dev_tools/lifecycle_playground.tscn with F6, or select M7 from dev_tools/test_playground.tscn. The isolated fixture has a three-second barrier, two mandatory checkpoints, a red DeathZone and yellow Finish. Jump over the hazard; F6 forces death; hold R/top face one second to reset once per hold; Escape returns to M6. The reset clears fixture progress and re-arms the barrier. All original M6 stations and bindings remain intact. Neither fixture accesses user profiles.
